# 阶段6：自动仿真 + 对话测试

> 目标：为 AgentStudio 提供**后台自动仿真**能力——用"仿真脚本"驱动 Agent 自动多轮对话，
> 验证不同客户画像/变量组合下的行为与旅程走向，产出可回看、可跳链路的执行记录。
> 2026-09-22 由原阶段3 任务 3.11 归并至此（优先级放后）；设计稿先行（`design/agentstudio/06-auto-simulation.html`）。
> 机制依据：`docs/03-production/09-客户信息与Variables覆盖机制.md`（客户级 Variables 覆盖 Agent 默认）。

---

## 1. 核心机制（为什么能模拟不同身份）

- **同一 Agent 构建默认值** = 变量值 key `agent:<id>`。
- **客户级覆盖** = `PUT /context-variables/{variable_id}/{customer_id}` body `{"data": ...}`；
  引擎按优先级 `customer.id > tag:* > agent:<id> > 全局` 取第一个非空值 → 客户级覆盖 Agent 默认。
- **每个仿真 run 用独立 customer_id** → 各自 PUT 客户级变量 → 同一 Agent、不同画像可得到不同旅程走向，
  互不干扰。

## 2. 交付物

### 后端（parlant-agent-server 扩展）
- MySQL 表：
  - `sim_configs`：仿真脚本（name / 客户配置 / variables JSON / 执行说明[背景·目标·步骤·结束条件] / 启用态）
  - `sim_runs`：执行记录（run_id / config_id / status / 轮次 / 工具调用数 / trace 关联 / 起止时间 / 结束原因）
- 端点：`GET/POST /api/sim/configs`、`PUT/DELETE /api/sim/configs/{id}`、
  `POST /api/sim/configs/{id}/runs`（启一次后台执行）、`GET /api/sim/runs`（执行记录列表，分页）、
  `POST /api/sim/runs/{id}/stop`。
- **执行器（后台任务）**：每个 run 一个独立 customer →
  ① `POST /api/customers` 建客户（name/metadata/tags）→
  ② 依执行说明 PUT 客户级变量覆盖 → ③ `POST /api/sessions` →
  ④ 循环「发消息 → SSE 收 Agent 回复 → **LLM 依"背景/目标 + 对话步骤 + 上一条回复"生成下一问** → 再发」 →
  ⑤ 终止条件（达到最大轮次 / 画像目标达成 / Agent 明确结束）→ 落 sim_runs；会话/轮次自动进 session_turns/会话记录。
- 提问生成：v1 用 LLM 按执行说明生成（可降级固定脚本）。

### 前端（parlant-agent-web `/auto-sim`，按 design/agentstudio/06）
- 仿真配置列表 + 新建/编辑脚本（**无 AgentId 字段，作用域=当前 Agent**）
- 执行：一键运行（可多次）、进度 + 逐轮日志（每轮 trace 链接）
- 执行记录：列表 + 查看记录（跳追踪与观测）

## 3. 验收标准

- [ ] 新建脚本（名称/客户配置/variables/执行说明）可保存、可多次执行
- [ ] 同一 Agent 下不同客户画像（如 `isSensitive=true` vs false）得到不同旅程走向
- [ ] 执行记录可回看逐轮对话，每轮可跳 langfuse 链路
- [ ] 结果进入追踪与观测的会话记录（session_turns）
