# 可观测性（Observability）

Parlant 内置支持 [OpenTelemetry](https://opentelemetry.io/)——业界标准的可观测性框架。这让你可以把追踪（traces）、指标（metrics）和日志（logs）导出到任意你偏好的后端，无论是 Jaeger、Grafana、Datadog，还是任何其他兼容 OpenTelemetry 的系统。

## 启用 OpenTelemetry

OpenTelemetry 通过环境变量启用。三大支柱（traces、metrics、logs）可以独立启用，各自通过设置对应的端点（endpoint）来开启。

| 变量 | 作用 |
| --- | --- |
| `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` | 启用追踪并指定 OTLP 端点 |
| `OTEL_EXPORTER_OTLP_METRICS_ENDPOINT` | 启用指标并指定 OTLP 端点 |
| `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` | 启用日志导出并指定 OTLP 端点 |

额外的配置项：

| 变量 | 作用 | 默认值 |
| --- | --- | --- |
| `OTEL_EXPORTER_OTLP_PROTOCOL` | OTLP 导出协议（`grpc` 或 `http/protobuf`） | `grpc` |
| `OTEL_EXPORTER_OTLP_INSECURE` | 允许不安全连接（禁用 TLS） | `false` |
| `OTEL_SERVICE_NAME` | 资源属性中的服务名 | `parlant` |
| `OTEL_METRIC_EXPORT_INTERVAL` | 指标导出间隔（毫秒） | `3000` |

### 示例配置

```
OTEL_EXPORTER_OTLP_METRICS_ENDPOINT=http://grafana-alloy.XYZ.svc.cluster.local:4318/v1/metrics
OTEL_EXPORTER_OTLP_LOGS_ENDPOINT=http://grafana-alloy.XYZ.svc.cluster.local:4318/v1/logs
OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=http://grafana-alloy.XYZ.svc.cluster.local:4318/v1/traces
```

用这些环境变量启动 Parlant 服务后，你会看到确认信息：

```
OpenTelemetry tracing is enabled.
OpenTelemetry metrics is enabled.
OpenTelemetry logging is enabled.
```

## 哪些内容会被追踪

Parlant 会自动为关键操作埋点（instrument）span 和指标，无需任何代码改动即可洞察智能体的行为。

### HTTP 请求

发往 Parlant API 的每个 HTTP 请求都会创建一个 span，包含：

* `http.request.id` - 唯一请求标识符
* `http.request.operation` - API 操作（如 `create_event`、`list_events`）
* `http.request.method` - HTTP 方法（GET、POST 等）
* 请求中的路径参数（path parameters）

### 引擎操作

对话引擎（conversation engine）会为众多操作创建 span，其中包括：

| Span 名称 | 描述 |
| --- | --- |
| `process` | 处理事件的主循环 |
| `utter` | 智能体话术生成 |
| `message_generation` | 消息组合流水线 |
| `guideline_matcher` | 指南匹配（包含 `phase` 属性："initial" 或 "reevaluation"） |
| `tool_caller` | 工具执行 |
| `response_analysis` | 回复质量分析 |

你还会看到更细粒度操作的 span，例如 LLM 或 embedder 调用。

### 指标

以下是 Parlant 导出的部分有用指标（还有其他）：

| 指标 | 类型 | 描述 |
| --- | --- | --- |
| `message_generation_duration` | Histogram | 端到端生成一条回复消息的耗时 |
| `ttfm_duration` | Histogram | 单次响应内的首条消息耗时（time-to-first-message） |
| `match_duration` | Histogram | 指南匹配耗时 |

## 将追踪与会话关联起来

Parlant 的追踪 ID（trace ID）设计用于帮助你把遥测数据与特定会话和事件关联起来。会话中的每个事件都包含一个 `trace_id` 字段，对应该事件所产生的 OpenTelemetry 追踪。

这意味着你可以：

1. 在前端发现一条有问题的回复
2. 查找到该事件的 `trace_id`
3. 在你的可观测性后端中搜索该追踪
4. 检查导致该回复的完整处理流水线

## 回退行为（Fallback Behavior）

如果没有配置 OpenTelemetry 端点，Parlant 会回退到轻量的本地实现：

* **追踪（Tracing）**：使用内存 tracer（in-memory tracer）
* **指标（Metrics）**：使用本地记录型 meter（logging meter）
* **日志（Logging）**：记录到 `parlant-data/parlant.log`

换句话说，你可以在没有任何可观测性基础设施的情况下进行本地开发，仅在需要时再启用它。
