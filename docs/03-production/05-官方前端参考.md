# 自定义前端 (Custom Frontend)

将 Parlant 集成到你的 React 应用中最快的方式，是使用我们官方的 [`parlant-chat-react`](https://github.com/emcie-co/parlant-chat-react) 组件。该组件提供了一个完整的聊天界面，可直接连接你的 Parlant Agent。

### 安装与基础配置

通过 npm 或 yarn 安装该组件：

```bash
npm install parlant-chat-react
# or
yarn add parlant-chat-react
```

然后将其集成到你的 React 应用中：

```jsx
import React from 'react';
import ParlantChatbox from 'parlant-chat-react';

function App() {
  return (
    <div>
      <h1>My Application</h1>
      <ParlantChatbox
        server="http://localhost:8800"  // Your Parlant server URL
        agentId="your-agent-id"         // Your agent's ID
      />
    </div>
  );
}

export default App;
```

### 配置选项

该组件支持多个配置属性（props）：

```jsx
<ParlantChatbox
  // Required props
  server="http://localhost:8800"
  agentId="your-agent-id"

  // Optional props
  sessionId="existing-session-id"     // Continue existing session
  customerId="customer-123"           // Associate with specific customer
  float={true}                        // Display as floating popup
  titleFn={(session) => `Chat ${session.id}`}  // Dynamic title generation
/>
```

### 事件获取：SSE 与长轮询（Events: SSE vs Long Polling）

#### SSE：推荐方式（SSE as the Recommended Approach）

与 Parlant 保持实时同步的**推荐方式**是服务器发送事件（SSE, Server-Sent Events）。向会话事件端点加上 `sse=true` 查询参数即可：

```text
GET /sessions/{session_id}/events?sse=true&min_offset=...&kinds=message,status
```

要点（均已在 v3.3.1 源码 api/sessions.py 确认）：

- `sse=true`：让连接保持打开、服务端持续推送新事件；配合浏览器原生 `EventSource`，**断线自动重连**（reconnect）由浏览器与协议层处理；
- `min_offset`：只接收该偏移量之后的新事件，断线恢复时用它续传，避免漏事件；
- `kinds`：**逗号分隔的字符串**，用于过滤事件类型，例如 `kinds=message,status`；
- `wait_for_data`（默认 60 秒）：在 SSE 模式下作为「两次事件之间的超时」——若长时间没有新事件，服务端会关闭流。

每个 SSE 帧是一条独立的事件 DTO（JSON），形如：

```text
data: {"id":"evt_...","kind":"status","source":"ai_agent","offset":7,"data":{"status":"typing"},...}

```

#### 长轮询：备选方式（Long Polling as a Fallback）

长轮询（long polling）仍然受支持，但已**降级为备选**——用于不支持 SSE 的环境。其语义与 SSE 一致：`GET /sessions/{id}/events?min_offset=...&wait_for_data=30` 会阻塞至多 30 秒等待新事件，超时后返回 504。具体实现见下文「步骤 5」。

### 状态事件（Status Events）

会话在处理过程中会推送以下 **5 种状态事件**：

| 状态 | 含义 | UI 建议 |
|---|---|---|
| `acknowledged` | 已收到客户消息，Agent 已确认接收 | 可显示「已接收」 |
| `processing` | Agent 正在处理 | 直接展示 `data.stage`（`Interpreting` / `Thinking`） |
| `typing` | Agent 正在组织回复文本 | 显示「正在输入…」 |
| `ready` | 本轮处理结束 | 收起「正在输入…」；但见下方警告 |
| `error` | 处理出错 | 显示错误并允许重试 |

> **警告**：`ready` 分为**「临时 ready」**与**「完成 ready」**两种——只有 `data.stage === "completed"` 才代表真正的完成。**不要仅凭 `status === 'ready'` 来判断 Agent 是否已经结束**（*Don't use `status === 'ready'` alone to detect that the agent is finished*）。一个健壮的 UI 应当在收到 `ready` 时先隐藏输入指示，等到 `completed` 到达后才把整条回复定型（见下文「总结：关键原则」第 5 条）。

### 流式消息（Streaming Messages）

对于 `MessageOutputMode.STREAM` 的 Agent，消息事件的文本按**增量**到达：

- `data.chunks` 是**不断累积的字符串数组**：每次推送追加新的文本片段；当数组末尾出现 `null` 时表示该条消息**完成**（*chunks accumulate; a trailing `null` signals completion*）；
- **block 与 streaming 的判定**：只要事件带 `data.chunks` 即为流式消息；否则为整块（block）消息，内容在 `data.message` 中；
- 即便 Agent 是 STREAM 模式，其**开场白（preambles）与预设话术（canned responses）仍然按 block 到达**，UI 需要同时兼容两种形态。

#### 双连接模式（Two-Tier SSE for Streaming）

要逐字（token 级）渲染流式回复，同时不丢失事件流的整体性，官网推荐**双连接**：

1. **会话级 SSE**：`GET /sessions/{id}/events?sse=true&kinds=message,status`——持续监听整个会话的新事件，维护偏移量；
2. **单事件级 SSE**：`GET /sessions/{id}/events/{event_id}?sse=true&wait_for_completion=true`——针对某一条消息事件跟踪它的增量追加（每次事件更新推一帧），直到完成（chunks 以 `null` 结尾）后自动关闭。

会话级负责「发现」，单事件级负责「渲染细节」，两层配合即可实现无缝的流式体验。

#### 步骤 4：用 SSE 监听会话事件（推荐）

建立会话级 SSE 连接。每个 `data:` 帧就是一条事件 DTO 的 JSON，直接解析即可；`EventSource` 会自动处理断线重连：

##### TypeScript

```typescript
private startEventMonitoring(): EventSource {
  if (!this.sessionId) throw new Error('No active session');

  const es = new EventSource(
    `${SERVER_URL}/sessions/${this.sessionId}/events` +
      `?sse=true&min_offset=${this.lastOffset}&kinds=message,status`
  );

  // 每帧 data 是单条事件 DTO 的 JSON
  es.onmessage = (event) => {
    const e = JSON.parse(event.data);
    this.handleEvent(e);
    this.lastOffset = Math.max(this.lastOffset, e.offset + 1);
  };

  es.onerror = () => {
    // EventSource 会自动重连；这里只需处理 UI 反馈（如显示“连接中断”）
  };

  return es;
}

private async handleEvent(event: any): Promise<void> {
  if (event.kind === "message") {
    this.displayMessage(event);
  } else if (event.kind === "status") {
    this.updateStatus(event);
  }
}
```

#### 步骤 5：长轮询（备选）

在不支持 SSE 的环境下，可退回长轮询。注意官网新版将其列为备选方案：

##### TypeScript

```typescript
private async startEventMonitoringByPolling(): Promise<void> {
  if (!this.sessionId) return;

  while (true) {
    try {
      // Poll for new events with long polling
      const events = await this.client.sessions.listEvents(this.sessionId, {
        minOffset: this.lastOffset,
        waitForData: 30, // Wait up to 30 seconds for new events
        kinds: "message,status" // 逗号分隔字符串
      });

      // Process each event
      for (const event of events) {
        await this.handleEvent(event);
        this.lastOffset = Math.max(this.lastOffset, event.offset + 1);
      }

    } catch (error) {
      console.error('Event monitoring error:', error);
      // Wait before retrying
      await new Promise(resolve => setTimeout(resolve, 5000));
    }
  }
}
```

#### 步骤 6：在 UI 中显示消息与状态

基于来自 Parlant 的事件实现 UI 更新。处理 5 种状态（含 processing 的 `data.stage`）与流式消息：

##### TypeScript

```typescript
private displayMessage(event: any): void {
  const messageElement = document.createElement('div');
  messageElement.className = `message ${event.source}`;

  // 流式消息：chunks 累积数组，末尾 null 表示完成
  if (Array.isArray(event.data.chunks)) {
    const text = event.data.chunks
      .filter((chunk: any) => chunk !== null)
      .join('');
    messageElement.textContent = text;
    // 之后可通过单事件级 SSE（见“双连接模式”）持续追加更新该气泡
  } else {
    messageElement.textContent = event.data.message ?? '';
  }

  // 按消息来源设置样式
  switch (event.source) {
    case 'customer':
      messageElement.classList.add('customer-message');
      break;
    case 'ai_agent':
      messageElement.classList.add('agent-message');
      break;
    case 'human_agent':
      messageElement.classList.add('human-agent-message');
      const agentName = event.data.participant?.display_name || 'Agent';
      messageElement.innerHTML = `
        <div class="agent-info">${agentName}</div>
        <div class="message-content">${event.data.message}</div>
      `;
      break;
  }

  // Add to chat container
  const chatContainer = document.getElementById('chat-messages');
  if (chatContainer) {
    chatContainer.appendChild(messageElement);
    chatContainer.scrollTop = chatContainer.scrollHeight;
  }
}

private updateStatus(event: any): void {
  const statusElement = document.getElementById('chat-status');
  if (!statusElement) return;

  switch (event.data.status) {
    case 'acknowledged':
      statusElement.textContent = 'Message received...';
      break;
    case 'processing':
      // data.stage: Interpreting / Thinking，直接展示
      statusElement.textContent =
        event.data.stage === 'Thinking'
          ? 'Agent is thinking...'
          : 'Agent is interpreting your request...';
      break;
    case 'typing':
      statusElement.textContent = 'Agent is typing...';
      break;
    case 'ready':
      // 临时 ready：先收起输入指示；真正的完成看 data.stage === 'completed'
      statusElement.textContent = '';
      break;
    case 'error':
      statusElement.textContent = 'Something went wrong. Please try again.';
      break;
  }
}
```

#### 步骤 7：跟踪流式消息增量（单事件级 SSE）

对某一条流式消息事件，可打开单事件级 SSE 实时跟踪其 chunks 追加，直到完成：

```typescript
// 针对某条消息事件，流式跟踪增量，直到完成（chunks 以 null 结尾）
private streamEvent(eventId: string): EventSource {
  const es = new EventSource(
    `${SERVER_URL}/sessions/${this.sessionId}/events/${eventId}` +
      `?sse=true&wait_for_completion=true`
  );

  es.onmessage = (event) => {
    const e = JSON.parse(event.data);
    // e.data.chunks 累积追加 → 更新对应消息气泡的文本
    this.updateStreamingMessageBubble(e.id, e.data.chunks);
  };

  // 事件完成（chunks 以 null 结尾）后服务端自动关闭流
  return es;
}
```

### API 参考（API Reference）

以下为构建自定义前端最常用的端点摘要（均已在 v3.3.1 源码 api/sessions.py 确认）。

#### 会话（Sessions）

- `POST /sessions` — 创建会话。查询参数 `allow_greeting`（默认 `false`）；请求体：`agent_id`、`customer_id`、`title`（**≤200 字符**）、`metadata`、`labels`、`consumption_offsets`；会话 `mode` 为 `auto`（自动回复）或 `manual`（手动模式）。
- `GET /sessions` — 列表查询。可按 `agent_id` / `customer_id` 过滤；支持**游标分页**：`limit` 取值 **1–100**，配合 `cursor` 翻页。
- `PATCH /sessions/{session_id}` — 更新会话：`title`、`metadata`、`labels`、`consumption_offsets`、`mode`。
- `DELETE /sessions/{session_id}` — 删除会话。

#### 事件（Events）

- `POST /sessions/{session_id}/events` — 向会话添加事件。`kind`：`message` / `status` / `tool` / `custom`；`source`：`customer` / `human_agent` / `ai_agent` / `system`（另含 `customer_ui` / `human_agent_on_behalf_of_ai_agent`）；`moderation`：`auto` / `paranoid` / `none`（**默认 `none`**）。
- `GET /sessions/{session_id}/events` — 读取事件。参数：`min_offset`（只取该偏移量之后）、`kinds`（**逗号分隔**）、`source`、`trace_id`、`wait_for_data`（**默认 60**，长轮询/SSE 超时）、`sse`（true 时返回事件流）。
- `GET /sessions/{session_id}/events/{event_id}` — 读取单条事件。`wait_for_completion=true` 会等待流式消息完成（chunks 以 `null` 结尾）；`sse=true` 流式跟踪该事件的增量更新直到完成。
- `DELETE /sessions/{session_id}/events?min_offset=N` — **永久删除**该会话中偏移量 ≥ N 的事件（不可撤销）。
- `PATCH /sessions/{session_id}/events/{event_id}` — 更新单条事件，**仅支持修改 `metadata`**。

### 总结：关键原则（Summary: Key Principles）

1. **Events-not-request-response（事件，而非请求-响应）**：一切 UI 状态都以 Parlant 推送的事件为准，不要把发送请求当作 UI 更新依据。
2. **Track offsets（跟踪偏移量）**：用 `min_offset` 维护消费位置，断线重连/轮询时续传，避免漏事件或重复渲染。
3. **Check chunks per message（逐消息检查 chunks）**：有 `data.chunks` 即流式消息，按其累积渲染；否则按整块消息渲染 `data.message`。
4. **Two-tier SSE for streaming（流式用双连接 SSE）**：会话级 SSE 发现新事件，单事件级 SSE 渲染流式增量。
5. **Hide on ready, finish on completed（收到 ready 收起指示，completed 才定型）**：不要仅凭 `status === 'ready'` 判断 Agent 结束。

这种方式让你在利用 Parlant 强大 Agent 能力的同时，对聊天体验拥有完全的控制权。你可以将此模式适配到任何前端框架或原生 JavaScript 实现中。
