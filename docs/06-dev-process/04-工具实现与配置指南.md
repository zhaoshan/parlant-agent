# 工具实现与配置指南（内置 + remote 自定义）

> 2026-09-23（内置）/ 2026-09-29（remote）核实。`agent-definition.json` 的 `tools[]`
> 分两类，**均由我们在 runtime `app/services/` 自研实现**，Parlant 框架只提供
> `@p.tool` 装饰器 + ToolEntry/ToolService 机制（函数体与语义归我们）：
>
> - **`source="builtin"` 内置工具**：`parlant-agent-runtime/app/services/builtin_tools.py`
>   里的 `journey_node_counter` / `variable_update` / `tavily_search`。
> - **`source="remote"` 自定义工具**：`parlant-agent-runtime/app/services/http_tools.py`
>   的**通用 HTTP 工具内核**——按 schema 声明的 `method/url/headers` 生成任意 HTTP 调用
>   工具，新增自定义工具 = 在 schema 声明一个 remote 工具，无需写代码。

---

## 0. 统一生效机制（为什么"配置了就能被调用"）

```
agent-definition.json tools[] 声明工具元数据（id/name/description/input_schema + source）
  → loader resolve_tool("工具名") 解析为 ToolRef
  → 挂到 tool 节点（journey tool_state）或指南 tools
  → SDK 收集 ToolEntry 注册进集成 "built-in" 工具服务（PluginServer.tools，key=工具名）
  → 引擎进入 tool 节点/命中指南 → ToolCaller 经 "built-in" 服务调用函数(context, **args)
  → 返回 ToolResult(data) 注入 Agent 上下文 → 决策下一步
```

**工具名解析顺序**（`builtin_tools.resolve_tool`）：**内置 `BUILTIN_TOOLS` 优先 →
remote 注册表兜底**（`http_tools.resolve_remote_tool`，loader 装配时已按 schema 声明生成）。

> 前提：`builtin_tools.py` / `http_tools.py` 在 runtime 进程内被导入（loader 引用它们）；
> `variable_update` 还需容器注入（`agent_loader.load` 调 `set_runtime_services(server.container)`）；
> remote 工具需 runtime 启动时 `register_remote_tools(definition.tools.tools)` 注册。

## 第一部分：内置工具（builtin_tools.py）

### 1. journey_node_counter —— 旅程节点访问计数器

- **含义**：按会话统计"进入某 tool 节点"的次数；典型用途：挽留次数计算（拒绝 N 次后转预约办理）。
- **实现**：`@p.tool` 函数，按 `(agent_id, session_id)` 内存字典计数 +1；`max_value` 可选，
  返回 `remaining` / `reached_limit`。
- **配置**：旅程 tool 节点 `tool_state: ["journey_node_counter"]`（转移条件直接读 `count`）。
- **局限**：按 `(agent_id, session_id)` 计数（同会话内多计数节点共享，节点维度需 ToolContext
  带节点 id，当前未暴露）；单进程内存，重启清零；多进程/多 pod（阶段5）需换 Redis。

### 2. variable_update —— 声明式会话变量写入

- **含义**：把声明变量写进会话变量，驱动旅程分支。
- **实现**：`@p.tool` 经注入的容器访问 `ContextVariableStore`；对 `variable_names` 中已声明的
  变量，取 `variable_selectors`（JSON 字符串，`{"varName":{"value":...}}`）里的 value，
  以 `key=customer_id` **客户级覆盖**写入（引擎按 `customer.id > agent:<id> > 全局` 读取，
  见 docs/06-dev-process/02）。
- **配置**：tool 节点 `tool_state: ["variable_update"]`；指南 `tools: ["variable_update"]`；
  调用方（LLM）传 `variable_names` + `variable_selectors` JSON。
- **局限**：值必须由调用方在 selectors 里给出；变量未声明/无 value 则回执状态不写。

### 3. tavily_search —— 联网搜索

- **含义**：Tavily 联网搜索，返回 title/url/content 摘要。
- **实现**：`@p.tool`，POST `api.tavily.com/search`（`TAVILY_API_KEY`）；未配置/异常返回提示不抛错。
- **配置**：tool 节点 `tool_state: ["tavily_search"]` 或指南 `tools: ["tavily_search"]`。

### 4. 新增内置工具的步骤

1. `builtin_tools.py` 加 `@p.tool async def xxx(context: p.ToolContext, ...) -> p.ToolResult`
   （首参必须 `context: p.ToolContext`，**不要用 `from __future__ import annotations`**——
   注解变字符串导致装饰器断言失败）。
2. 加入 `BUILTIN_TOOLS` 字典，`resolve_tool` 自动覆盖。
3. schema `tools[]` 里声明同名工具（`source="builtin"`），供配置引用。

## 第二部分：remote 自定义工具（http_tools.py）

> 平台能力：构建页「新建工具」的 `source: remote` 从纯 schema 字段升级为**可执行的通用
> HTTP 工具**（2026-09-29）。远程服务示例：`invest-advisor-demo/`（文件存储 FastAPI，:8300）。

### 5. 机制

每个 remote 工具 = **一个绑定自身 HTTP 配置的闭包 ToolEntry**，共享一个通用 HTTP 执行内核：

- `make_http_tool(tool_def)`：按 schema 声明的 `method/url/headers/input_schema` 生成 ToolEntry，
  用 `_tool_decorator_impl` + 合成 `__signature__` 让每个 remote 工具对 LLM 暴露自己的业务参数。
- `_http_invoke`：通用内核。发出请求、支持动态 header / request_body、自动注入 `context.customer_id`。
- `register_remote_tools`：loader `load()` 时按 schema 声明生成并注册（幂等：同名复用）。
- `resolve_tool(name)` 内置未命中时兜底查 remote。

### 6. URL / body 映射规则（remote 工具声明按此写）

1. **url 模板可含 `{param}` 占位**：调用时用同名业务参数填充。
   ```json
   { "url": "http://127.0.0.1:8300/customer/{customer_id}" }
   ```
2. **customer_id 自动注入**：业务参数未给 `customer_id` 时，从 `context.customer_id`
   （会话客户维度）注入 → 客户身份自动切换。
3. **GET**：剩余业务参数拼 query string；**POST/PUT**：进 JSON body。
4. **固定 header** 来自声明 `headers`；**动态 header** 经 `headers` 参数（JSON 字符串，
   LLM 可按需传）合并覆盖。
5. **request_body 参数**（JSON 字符串）存在时整体覆盖 body（精细化控制）。

### 7. schema 形态（remote 工具新增字段）

```json
{
  "id": "assess_risk",
  "name": "assess_risk",
  "source": "remote",
  "type": "http",
  "method": "POST",
  "url": "http://127.0.0.1:8300/risk/assess",
  "headers": { "Content-Type": "application/json" },
  "timeout_seconds": 10,
  "consequential": true,
  "input_schema": {
    "type": "object",
    "properties": { "risk_level": { "type": "string", "enum": ["C1","C2","C3","C4","C5"] } },
    "required": ["risk_level"]
  }
}
```

`ToolDef` 新增 `method / url / headers` 字段（`app/models/definition.py`）；前端 `ToolDef` 类型
+ 构建页工具编辑器同步（remote 时显示 method/url/headers 配置区）。

### 8. 新增自定义（remote）工具的步骤

1. 后端服务就绪（任意 HTTP 接口，内网直连）。
2. schema `tools[]` 声明 remote 工具（method/url/headers/input_schema），
   URL 用 `{customer_id}` 占位做客户维度注入。
3. 挂到旅程 tool 节点 `tool_state` 或指南 `tools`。
4. 若需变量联动（按客户刷新），在变量编辑页关联该工具 + freshness_rules（见第三部分）。

### 9. ⚠️ 已知限制（安全/沙箱，列为待办）

- **无 SSRF 防护**：url 来自 schema 声明（非 LLM 直传），但未校验目标主机范围。
- **无鉴权/加密**：远程服务需自行处理。
- **无超时重试分级**：仅单次 httpx timeout。
- **内核函数体 trust_env=False**：内网/本地服务直连，避开本机系统代理劫持（macOS :7899 → 502）。
- **4xx/5xx 不抛错**：`_http_invoke` 对非 2xx 返回 `ToolResult(data={"error": "HTTP 404", "detail": ...})`
  ——LLM 可见该错误（「客户档案校验 → 未找到 → 结束会话」的旅程分支正依赖此语义），
  但调用方视角"成功"返回，需要业务侧判断 error 字段。

## 第三部分：工具 ↔ 变量 freshness 联动（按客户自动刷新）

变量编辑页两个字段共同驱动（无需写代码）：

- **工具（动态刷新）**：绑定一个数据工具（remote 如 `get_customer_profile`，或内置 `tavily_search`）。
  编辑页为**下拉**：定义内声明的工具 + 「无」+「其它（内置/自定义）…」转手输。
- **刷新规则 freshness_rules**：cron 表达式，如 `0 * * * *`（每小时）。

链路：

```
变量编辑页 [工具 + freshness_rules] → schema（tool / freshness_rules）
  → loader _build_variables: create_variable(name, tool=resolve_tool(var.tool), freshness_rules=...)
  → 引擎 cron 到期 → 以**空参数**自动调该工具 → remote 内核自动注入会话 customer_id
  → 工具结果写入变量存储（key=customer.id，最高优先级）→ 注入 LLM 上下文驱动指南/旅程分支
```

**已验证**（智能投顾 5 变量绑定 `get_customer_profile`）：会话按 customer_id 拉取业务画像写入
变量（`risk_level` 变量在 cus_002 键下 = 李女士完整画像含 C4）；已测评客户跳过测评、未测评走
测评，均由变量里的画像驱动 sta_A 分叉（见 `docs/05-sample-agents/智能投顾Agent需求.md` §8）。

> 注意：变量值存的是**工具完整返回**（`{status, data:{...}}`），不是只存对应字段——LLM 自行
> 提取。若想"每变量只存自己字段"需工具按字段抽取（当前 `_http_invoke` 返回整响应）。

## 第四部分：前端配置

- **工具编辑器**（构建页 → 工具）：`builtin` 名称只读；`remote` 显示 method/url/headers 配置区
  （`TableModules.tsx` Tools 组件）。
- **变量编辑器**（构建页 → 变量）：工具关联为**下拉**（定义内工具 + 无 + 其它手输），
  freshness_rules 为 cron 输入（`TableModules.tsx` VariableToolField）。

## 第五部分：踩坑清单

1. **`@p.tool` 只支持 `list` 泛型**，dict 抛错 → `variable_selectors` 用 `str`（JSON 字符串）承载。
2. **勿用 `from __future__ import annotations`**（注解变字符串 → 装饰器断言失败）。
3. **服务间 502**：runtime↔demo 的 httpx 客户端 `trust_env=False` 直连，避开 macOS 系统代理
   （:7899）劫持 127.0.0.1。
4. **remote 非 2xx 是"成功返回 error"**：调用方/旅程需判断 `data.error`，不是抛异常。
5. **tool 节点必须补 REEVALUATION 关系**（loader `_build_journey` 已处理）：直接 `_create_state`
   绕过 SDK `_transition` 的关系创建 → 迭代2 重评估反查不到 → tool→fork 不推进。
6. **同名 remote 工具幂等复用**：`register_remote_tools` 同名跳过（id 相同视为同一定义）；
   两个 Agent 声明同名但不同实现的工具会静默共享第一个——避免这样做。
7. **变量 tool 未在定义内声明也可用**（如内置 `tavily_search`）：前端下拉走「其它」手输，
   loader `resolve_tool` 内置兜底解析。
8. **`input_schema.required` 必须被 `make_http_tool` 转发**（2026-10-01 修）：早期合成签名把
   所有业务参数都设 `default=None` → 引擎 `tool.required` 恒为空 → 必填校验空转，缺参也照发
   HTTP（实测智能投顾 `assess_risk` 缺 `risk_level` → demo 422，且**引擎必填校验
   `single_tool_batch` 的 CANNOT_RUN 拦截失效**）。现在必填参数合成签名**不带默认值**
   （parlant：无默认值=required），缺参时引擎拒调工具并回传 missing_data，模型必须先问客户。
   **验证方式**：`make_http_tool(td).tool.required` 应含必填参数名。

## 与框架的关系

- **机制归框架**：`@p.tool` 装饰器、ToolEntry/ToolRef、集成 "built-in" 工具服务、ToolCaller 调用。
- **实现归我们**：内置工具函数体、计数/写入语义、错误处理；remote 通用 HTTP 内核与声明式配置。
- 若 Parlant 后续原生提供同名工具，需评估优先级（外部 ToolService 注册 vs 内置声明）。
