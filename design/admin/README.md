## 1. 设计系统

### 布局骨架（三栏）

```
┌──────────┬──────────────────────────────────────────────┬────────────┐
│ 全局侧栏  │ Agent 上下文栏（名称/未发布徽标/版本/操作）        │            │
│ 200px    ├──────────┬───────────────────────────────┤  检查器     │
│ 深色     │ 组件导航  │            工作区              │  330-400px │
│ 固定     │ 196px    │   列表 / 画布 / 表格           │  随选中变化 │
└──────────┴──────────┴───────────────────────────────┴────────────┘
```

- **深色侧栏** `#0B1220`：全局导航（Agents / 对话仿真 / 追踪与观测 / 设置）+ 服务状态。
- **明亮工作区** `#F7F8FA`：承载所有编辑内容；信息密度 8/10（紧凑表格 + master-detail）。
- 记忆点只留给**旅程状态机画布**（节点类型色编码），其余界面全部克制。

### 色彩 Token

| 角色 | 值 | 用途 |
|---|---|---|
| `--primary` | `#4F46E5` | 主按钮、选中态、链接 |
| `--success` | `#059669` | 已发布、alive、Tool 节点 |
| `--warning` | `#B45309` | 未发布更改、草稿条、Fork 节点 |
| `--danger` | `#DC2626` | 删除、高严重级别 |
| `--ink / --muted` | `#0F172A / #94A3B8` | 正文 / 辅助 |
| `--line` | `#E4E7EC` | 发丝分隔线（非卡片阴影） |

节点类型色：**chat=靛蓝 · tool=绿 · fork=琥珀 · entry=深灰**。

### 字体

- 界面：**IBM Plex Sans**（400/500/600/700）——开发者工具的精确感，避开 Inter 默认感。
- 代码/ID/条件表达式：**JetBrains Mono**。
- 字阶：12（辅助）/ 12.5（正文）/ 13（导航）/ 14（Agent 名）/ 18-19（页面标题）。

### 反模板约束（frontend-design）

- 不用全大写 eyebrow、不用序号装饰、不用渐变压纹、不用统一圆角卡片堆 + 灰色投影。
- 分隔一律发丝线；卡片阴影仅在悬浮/选中时出现。

## 3. 关键交互决策

1. **草稿/发布模型**：编辑即草稿，顶栏常驻"未发布更改"徽标 + `保存草稿`/`发布新版本`；发布后新会话生效、进行中会话保持原行为（与 Parlant 会话 offset 机制一致）。
2. **回滚即新版本**：回滚历史版本时创建并发布一个新版本号（如 v1.0.1），不覆盖历史；写审计日志。
3. **旅程画布校验**：发布前静态校验（出边缺失、死节点、变量未定义），警告条常驻画布底部。
4. **JSON 导入导出**：顶栏一级操作；导入走 schema 校验 → 错误定位 → 生成草稿。
5. **试跑入口**：顶栏"试跑"跳转 `/agents/:id/simulate`（对话仿真，阶段4范围）。

## 4. 待确认问题

1. **整体气质**：深色侧栏 + 明亮工作区（当前稿）vs 全暗色工作台？倾向保持当前（长时间配置编辑，明亮区更不易疲劳）。
2. **旅程编辑器**：默认水平自动布局（当前稿）是否够用？是否需要泳道/分组（按业务阶段着色）？
3. **指南编辑**：master-detail（当前稿）vs 表格行内展开编辑？master-detail 更适合长条件/动作文本。
4. **侧栏导航范围**：当前含"对话仿真 / 追踪与观测 / 设置"，是否接受，还是 MVP 只保留 Agents？
5. **字体**：IBM Plex Sans + JetBrains Mono 是否认可（需要引入 Google Fonts；内网部署可换本地字体包）。
